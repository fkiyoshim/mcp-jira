# Objetivo do Documento
Esse documento objetiva a especificação das integrações realizadas entre o módulo Reconciliador do CPqD e-TICS e o CPqD GI-FTTx.
# Definições e abreviaturas
Abreviatura
Definições
e-TICS ou CPqD e-TICS
Sistema CPqD de gerência de inventário de planta externa e interna
GI-FTTx ou CPqD GI-FTTx
Sistema CPqD de gerência de rede, com funções de gerência de falhas, desempenho e configuração (de recursos e serviços)
OLT
Optical Line Terminal
GPON
Gigabit Passive Optical Network
ONT
Optical Network Terminal
ISP
Módulo de gerência de planta interna do e-TICS
e-TICS Reconciling Service ou Recon ou Reconciliador
Módulo do e-TICS responsável pela reconciliação que consiste no processo de comparação do cadastro de rede (ISP) com as informações oriundas dos sistemas de gerência de rede (GI-FTTx). Este processo tem como objetivo, checar se as informações do cadastro são compatíveis com as informações obtidas pelos sistemas de gerência.
WSDL
Web Service Definition Language
NMS
Network Management System
# Descrição Funcional
A integração permitirá que o módulo e-TICS Reconciling Service possa se comunicar com o GI-FTTx a fim de recuperar os dados dos equipamentos e realizar o batimentos das informações obtidas em cada sistema.
Através desta integração, o e-TICS deverá consumir os web-services disponibilizados pelo GI para obter os equipamentos GPON a partir de um intervalo de IPs.
Para isto, o GI disponibilizará um web-service que retorna os identificadores dos equipamentos descobertos na rede a partir do intervalo de IPs, e outro que, a partir do identificador, retorne os detalhes do OLT, bem como, toda a hierarquia abaixo dele, que será composta pelos seguintes elementos:
GPON;
Placas de cada slot do GPON;
Para placas com função “OLT” ou “Switch”:
Portas de cada placa;
Para portas de placas com função “OLT”:
ONTs conectados às portas;
Portas de cada ONT;

# Sistemas envolvidos
GI-FTTx – Será responsável por validar os parâmetros de entrada, e a partir deles realizar a descoberta dos equipamentos no intervalo de IPs, retornando suas configurações
e-TICS Reconciling Service – Será responsável por acionar os serviços disponibilizados pelo GI para obter os equipamentos descobertos na rede através dos intervalos de IP, e realizar o batimento das informações.
# Periodicidade de atualização
Sob demanda do GI-FTTx.
# Definição do mecanismo de integração
A solução adotada para a integração será a utilização de serviços, através dos quais o GI-FTTx disponibilizará ao e-TICS, os dados sobre os equipamentos GPON existentes na rede para que o reconciliador possa realizar o batimento dos dados existentes na rede com os dados de inventário cadastrados no ISP. Neste contexto, a tecnologia adotada será a utilização de web-services, conforme Figura 02.
Para consumo do Reconciliador ao web-service do GI, foi adotado o padrão Axis.
Fig. 02 – Detalhamento do mecanismo de integração, baseado em serviços
Os dados dos equipamentos serão obtidos através dos mecanismos de descoberta do GI.
Para identificação única dos elementos dos GPON do GI foi estabelecido o seguinte padrão:
GPON - nome do GPON
Placas do GPON - IP:número do slot
Portas das placas – IP:número do slot:número da porta
ONTs conectados às portas – IP:número do slot:número da porta:identificação da ONT
Através deste padrão, o Reconciliador poderá associar os elementos do GI com os elementos correspondentes no ISP, para, posteriormente efetuar a comparação de seus dados.
Devido ao alto volume de dados, o Reconciliador utiliza dois serviços disponibilizados pelo GI para obter os dados do equipamentos GPON a partir dos IPs:
O primeiro serviço retorna apenas os nomes dos equipamentos encontrados que correspondem aos filtros informados. O detalhamento deste serviço se encontra na seção 6 - item a, deste documento.
O segundo serviço retorna toda a configuração dos equipamentos a partir de seus nomes (retornados pelo serviço de nomes descrito anteriormente). Estas informações são utilizadas pelo Reconciliador para que haja o batimento entre o cadastro do inventário e a descoberta do equipamento na rede. O detalhamento deste serviço se encontra na seção 6 - item b, deste documento.
Para realizar a correspondência entre equipamentos GPON será utilizado o IP do equipamento GPON no GI-FTTx e o IP do OLT no ISP. Eles serão obtidos da seguinte forma:
No GI-FTTx: O IP não é um atributo do GPON. Ele é um componente do nome dos slots do GPON (conforme padrão descrito anteriormente). Como todos os slots de um equipamento possuem o mesmo IP, e todos os equipamentos GPON retornados pelo serviço terão slots com placas associadas, ele será extraído a partir do nome de um dos slots daquele equipamento. Este dado será obtido através do serviço de configuração de equipamentos.
No ISP: O IP do equipamento GPON se encontra cadastrado no atributo “IP da gerência” presente no objeto “OLT”.
Na especificação dos serviços do GI-FTTx, não foi estabelecido um limite de registros disponibilizados em uma consulta.
# Definição dos fluxos
A solicitação ocorre sempre no sentido CPqD e-TICS - GI-FTTx, que por sua vez responde ao CPqD e-TICS de acordo com o solicitado. Detalhes sobre as informações trocadas entre os fluxos encontram-se na seção 7 – Definição dos Dados e [Ref. 01].
No total temos dois fluxos, descritos a seguir e representados na Figura 03:
a) fluxo Busca de Nomes de Equipamentos: Através deste serviço disponibilizado pelo GI-FTTx, é possível recuperar os equipamentos por nome do fabricante, por IPs ou ainda por faixa de IPs. Ele é responsável por retornar apenas os nomes dos equipamentos OLTs e dos seus slots a partir dos filtros de entrada utilizados que podem ser Fabricante ou por IPs ou faixa de IPs (estes filtros se encontram detalhados na seção 7.1.1 deste documento).
Para os filtros de entrada definidos, são associados os seguintes tratamentos:
Não há filtro de entrada definido: Serão considerados todos os equipamentos GPON descobertos pelo GI-FTTx;
Apenas filtro de fabricante foi definido: Serão considerados todos os equipamentos GPON, descobertos pelo GI-FTTx que sejam do fabricante definido. É permitido acionar o serviço utilizando no máximo um fabricante por solicitação;
Apenas filtro por IP ou intervalo de IPs foi definido: Serão considerados todos os equipamentos GPON cujo endereço IP atenda ao critério de filtro, independentemente de seus fabricantes. É permitido acionar o serviço utilizando mais de um IPs ou intervalos de IPs, utilizando neste caso uma lista de IPs ou de intervalos de IPs, ou ambos;
Se ambos os filtros forem fornecidos: Serão considerados todos os equipamentos GPON com endereço IP que atenda aos critérios da lista de IPs/intervalos de IPs e que sejam do fabricante definido.
É possível que o retorno deste serviço seja uma lista vazia, caso não sejam descobertos equipamentos com os filtros de entrada utilizados.
Caso ocorra um erro de processamento no GI-FTTx, ele retornará uma exceção, invalidando todo o retorno.
Através deste serviço, o Reconciliador recupera os equipamentos pelos intervalos de IPs requeridos. O parâmetro Fabricante não é utilizado atualmente na integração com o GI-FTTx.
b) fluxo Busca de Configuração dos Equipamentos: Através deste serviço, disponibilizado pelo GI-FTTx, é possível recuperar a configuração dos recursos, a partir do nome do recurso (este filtro se encontra detalhado na seção 7.1.2 deste documento).
Para o filtro de entrada definido, são associados os seguintes tratamentos:
É necessária a entrada de pelo menos um parâmetro válido para a realização deste serviço;
É possível incluir, como filtro de entrada, um ou mais nomes de recursos de tipos iguais ou diferentes;
Para cada recurso da lista de nomes de recursos, será considerado o próprio recurso e todos os recursos hierarquicamente abaixo dele.
Para cada recurso especificado nos parâmetros de entrada, devem ser retornados os dados de configuração de todos os recursos (vide seção 7.2.2 deste documento) que estão hierarquicamente abaixo do recurso, conforme descrito abaixo:
Se o parâmetro de entrada for um equipamento NE GPON: o serviço deverá retornar os dados de configuração de todas as placas associadas ao equipamento e para cada placa OLT, as portas GPON associadas e para cada porta GPON, as ONTs associadas e suas respectivas portas. Caso a placa seja Switch, Controladora+Switch ou TDM, suas portas também deverão ser retornadas.
Se o parâmetro de entrada for uma placa: o serviço deverá retornar os dados da placa. Caso a placa seja OLT, deverá retornar todas as portas GPON e ONTs associadas e suas respectivas portas. Caso a placa seja Switch, Controladora+Switch ou TDM, suas portas também deverão ser retornadas. Caso a placa tenha outro tipo, somente os dados da placa em questão serão retornados.
Conforme especificado acima, este serviço permite busca de configuração, somente a partir de um equipamento NE GPON ou de uma placa.
Assim sendo, a hierarquia de elementos, que este serviço retorna, segue abaixo:
Equipamento GPON;
Slots com placas associadas do equipamento;
Caso o slot seja do tipo Switch, Controladora+Switch, TDM ou OLT: portas do slot;
Caso a porta seja de um OLT: ONTs conectados às portas;
Caso haja ONTs: portas dos ONTs.
Caso não sejam encontrados recursos, a partir do filtro de entrada, será retornada uma lista vazia.
Caso ocorra um erro de processamento no GI-FTTx, ele retornará uma exceção, invalidando todo o retorno.
Através deste serviço, o Reconciliador recupera a configuração dos equipamentos utilizando como parâmetro de entrada o nome de um equipamento NE GPON. A busca através de nomes de placas não é utilizada. Com base no retorno deste serviço, o Reconciliador recupera todos os dados que serão comparados para que o batimento dos dados seja feito com o cadastro de inventário.

# Definição dos dados
A definição do WSDL para os dados de entrada e saída, bem como de seus tipos encontra-se no Anexo I neste documento.
Nota 1: O WSDL atual, disponibilizado pelo GI-FTTx, não trata a obrigatoriedade dos campos. Sendo assim, a obrigatoriedade dos campos, exposta nas tabelas a seguir, foi definida com base nos documentos de Requisitos do Reconciliador [Ref.1] disponibilizado pelo GI, e no documento de Integração FTTx, sendo validadas através do serviço do GI-FTTx disponibilizado pela DRC. A obtenção dos nomes, tipos e domínios dos campos foi realizada com base no WSDL.
Nota 2: Os tamanhos dos campos não foram definidos nos documentos, como também não existe definição no WSDL. Portanto esta informação não será apresentada nas tabelas que seguem.

# Mensagens de Erro
# Busca de Nomes de Equipamentos
Nos casos de erro, são retornados objetos do tipo “GiFTTxException”, porém não temos documentação referente aos possíveis erros que esta exceção pode retornar.
# Busca de Configuração de Equipamentos
Nos casos de erro, são retornados objetos do tipo “GiFTTxException”, porém não temos documentação referente aos possíveis erros que esta exceção pode retornar.
# Segurança
Não foi especificado nenhum mecanismo de segurança que exija qualquer tipo de autenticação para acesso aos serviços do GI-FTTX.
